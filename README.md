# Система контролю версій Git та сервіс GitHub Pages

## 1. Коротка інформація про системи контролю версій та Git
* **Система контролю версій (VCS)** — це програмне забезпечення, що дозволяє відстежувати зміни у файлах, зберігати історію редагувань та повертатися до попередніх станів коду.
* **Git** — це безкоштовна розподілена система контролю версій з відкритим початковим кодом, створена Лінусом Торвальдсом у 2005 році. Завдяки розподіленій архітектурі кожен розробник має повну локальну копію всієї історії проєкту на своєму комп'ютері.

---

## 2. Основні можливості та переваги використання Git
* **Розподілена робота:** Робота офлайн із можливістю подальшої синхронізації з віддаленим сервером.
* **Гнучке розгалуження (Branching):** Легке створення та швидке злиття гілок для розробки окремих функцій без ризику зламати основний код.
* **Висока швидкість:** Усі операції з кодом та історією відбуваються майже миттєво локально.
* **Надійність і цілісність даних:** Використання криптографічних хешів (SHA-1 / SHA-256) унеможливлює непомітну зміну історії чи файлів.

---

## 3. 10 базових команд для роботи в системі Git
1. `git init` — ініціалізація нового локального Git-репозиторію у поточній директорії.
2. `git clone <url>` — клонування існуючого віддаленого репозиторію на локальний комп'ютер.
3. `git status` — перегляд поточного стану робочого каталогу та індексованих (staged) змін.
4. `git add <file>` — додавання змін із робочого каталогу до індексу для подальшого коміту.
5. `git commit -m "Опис змін"` — фіксація збережених у індексі змін у локальній історії з описовим коментарем.
6. `git branch` — перегляд списку існуючих локальних гілок.
7. `git checkout -b <branch-name>` — створення нової гілки та автоматичний перехід на неї.
8. `git pull` — отримання та автоматичне злиття останніх змін із віддаленого репозиторію у поточну гілку.
9. `git push origin <branch>` — відправка локальних фіксованих комітів у віддалений репозиторій.
10. `git log` — перегляд історії комітів поточного проєкту.
